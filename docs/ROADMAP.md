# 손주야놀자 개발 로드맵

손주가 놀아주듯 매일 챙겨주는, 어르신이 매일 들를 이유가 있는 서비스를 만든다.

## 개요

**손주야놀자**는 60대 이상 고령층을 위한 **비로그인 콘텐츠 허브 + AI 말벗 챗봇** 서비스로 다음 기능을 제공합니다:

- **두뇌 건강 퀴즈** (F001~F003): 노래 맞추기 / 상식 퀴즈 / 기억력 게임 + AI 격려 코멘트
- **두뇌 게임** (F004~F005): 카드 매칭, 숫자 순서 맞추기(슐테 표)
- **매일 바뀌는 콘텐츠** (F006~F008): 건강 상식 카드, 어르신 인기 유튜브 순위, 오늘의 날씨·운세
- **AI 말벗 챗봇** (F009~F010): 잡담·회상형 대화 + 단계형 이용 제한(무료 → 광고 → 구독)
- **지원 기능** (F011~F015): 인증, 접근성 설정, 구독 결제, 리워드 광고, 마이페이지

상세 요구사항은 [docs/PRD.md](./docs/PRD.md)를 참조합니다.

## 현재 상태 (2026-09-06 기준)

- Next.js + Supabase 스타터킷의 데모/튜토리얼 코드 **제거 완료**
- 기존 Supabase Auth 화면(`app/auth/*`: 로그인/회원가입/비밀번호 찾기·변경) **재사용 가능 상태로 유지**
- 미들웨어(`lib/supabase/proxy.ts`) **화이트리스트 방식 적용 완료**
  - 로그인 필요: `/chat`, `/mypage`, `/subscribe` 3개 경로만
  - 그 외 전 경로 비로그인 접근 가능, 로그인 성공 시 `?redirect=`로 원래 경로 복귀
- Docker → Docker Hub → 오라클 클라우드 k3s 배포 파이프라인 **기존 자산 재사용**
- ✅ **Phase 1(애플리케이션 골격)·Phase 2(디자인 시스템/UI 완성) 완료** — 라우트·타입·DB 스키마·접근성 토큰·전역 위젯·전 페이지 더미 UI 구축 완료
- **PRD 실기능(F001~F010, F013~F015)은 아직 미구현** — Phase 3부터 실기능 개발 착수

**📅 최종 업데이트**: 2026-09-06
**📊 진행 상황**: Phase 3 완료, Phase 4 착수 대기 (8/25 Tasks 완료)

## 개발 워크플로우

본 로드맵은 **상위 단계(Phase)와 우선순위**를 정의합니다. 실제 개발 태스크는 각 Task를 **shrimp-task-manager로 잘게 분해**하여 진행합니다.

1. **작업 계획**
   - 기존 코드베이스를 학습하고 현재 상태를 파악
   - 착수할 Task를 shrimp-task-manager로 세부 태스크 분해
   - 해당 Phase의 "진행 전 확정 필요" 항목이 모두 결정되었는지 먼저 확인

2. **작업 생성**
   - 고수준 명세, 관련 파일, 수락 기준, 구현 단계 포함
   - API/비즈니스 로직 작업에는 "테스트 체크리스트" 섹션 필수 포함(Playwright MCP 시나리오)

3. **작업 구현**
   - UI 컴포넌트와 비즈니스 로직을 분리하고, Supabase 호출은 데이터 레이어로 감싼다
   - 접근성 하한선(본문 16pt+, 대비 7:1+, 터치 44x44px+, 아이콘 단독 사용 금지)은 매 구현마다 검증
   - API 연동·비즈니스 로직 구현 시 **Playwright MCP로 E2E 테스트 수행 필수**
   - 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**
   - 완료된 Task를 ✅로 표시하고, Phase 전체 완료 시 Phase 제목에도 ✅ 표시

## ✅ Phase 1: 애플리케이션 골격 구축

전체 라우트와 타입, 데이터 스키마를 먼저 세워 이후 Phase가 병렬로 진행될 수 있게 합니다.

- ✅ **Task 001: 전체 라우트 구조 및 페이지 스캐폴딩** - 우선순위
  - App Router 기반 전 페이지 빈 껍데기 생성: `/`, `/quiz`, `/quiz/play/[type]`, `/quiz/result`, `/games`, `/games/play/[type]`, `/chat`, `/mypage`, `/subscribe`
  - 기존 `app/auth/*` 라우트는 유지하고 신규 인증 화면을 만들지 않음
  - 루트 레이아웃에 공통 헤더/푸터 골격 배치(홈 / 말벗 챗봇 / 글자크기·고대비 위젯 / 인증 메뉴)
  - 미들웨어 보호 경로(`/chat`, `/mypage`, `/subscribe`)와 실제 라우트 경로 일치 검증
  - 각 페이지 간 이동 링크를 연결해 PRD 사용자 여정 전체를 클릭으로 순회 가능하게 함

- ✅ **Task 002: 도메인 타입 정의 및 데이터 레이어 인터페이스 설계**
  - PRD 데이터 모델 기반 TypeScript 타입 정의(`profiles`, `daily_contents`, `health_tips`, `youtube_rankings`, `chat_usage`, `chat_messages`, `quiz_sets`, `quiz_attempts`, `brain_game_attempts`, `subscriptions`)
  - 퀴즈 문제 `questions` jsonb 구조 및 퀴즈 유형(`song`/`trivia`/`memory`), 게임 유형(`card_matching`/`schulte_table`) 유니온 타입 확정
  - 화면 컴포넌트가 Supabase를 직접 호출하지 않도록 **데이터 레이어 인터페이스**(리포지토리 형태) 시그니처 정의 — 향후 네이티브 앱에서 동일 레이어 재사용 목표
  - Claude API / YouTube Data API 응답 타입 정의
  - 도메인 로직(채점, 이용 횟수 판정)을 UI 비의존 순수 함수로 둘 위치 확정

- ✅ **Task 003: Supabase 데이터베이스 스키마 및 RLS 설계**
  - PRD 10개 테이블 마이그레이션 작성
  - `auth.users` 가입 시 `profiles` 자동 생성 트리거 설계
  - RLS 정책 설계: 공용 콘텐츠(`daily_contents`, `health_tips`, `youtube_rankings`, `quiz_sets`)는 익명 읽기 허용, 개인 데이터(`chat_*`, `subscriptions`, `profiles`)는 본인만 접근
  - 비로그인 기록 허용 테이블(`quiz_attempts`, `brain_game_attempts`의 `user_id` nullable) 정책 정의
  - 배치 생성 콘텐츠 조회 성능을 위한 `date`/`fetched_at` 인덱스 설계

## ✅ Phase 2: 디자인 시스템 및 UI 완성 (더미 데이터)

접근성 하한선을 토큰 레벨로 강제하고, 모든 화면을 더미 데이터로 완성해 사용자 여정을 먼저 검증합니다.

- ✅ **Task 004: 접근성 디자인 토큰 및 공통 컴포넌트 라이브러리 구축**
  - ✅ Tailwind 테마에 접근성 하한선을 토큰화: 본문 16pt 이상, 핵심 정보 20pt 이상, line-height 1.6 이상
  - ✅ 대비 7:1을 만족하는 컬러 팔레트 확정(딥네이비/테라코타 계열 포인트 + 뉴트럴 배경) 및 대비 검증
  - ✅ 최소 44x44px 터치 영역이 기본값인 shadcn/ui 기반 Button/Card/Dialog 등 공통 컴포넌트 정의
  - ✅ 아이콘 단독 사용을 막는 텍스트 라벨 병기 규칙을 컴포넌트 API 레벨에 반영
  - ✅ 카드형 레이아웃 + soft shadow + 넉넉한 radius의 모던 톤 적용, 과한 모션(자동 캐러셀 등) 배제

- ✅ **Task 005: 전역 레이아웃 및 접근성 전역 위젯 구현**
  - ✅ 헤더 메뉴 4개 이내 유지(홈 / 말벗 챗봇 / 글자크기·고대비 / 인증)
  - ✅ 글자 크기 3단계(보통/크게/아주크게) 및 고대비 모드 토글 위젯 구현 — 이 단계에서는 클라이언트 로컬 상태로 동작
  - ✅ "보통" 단계가 이미 접근성 하한선을 만족하는지 검증
  - ✅ 로그인/비로그인 상태별 헤더 메뉴 분기

- ✅ **Task 006: 전 페이지 UI 완성 (하드코딩 더미 데이터)**
  - ✅ 홈 콘텐츠 허브: 날씨·운세 요약 상단, 5개 콘텐츠 카드, 건강 상식 카드 인라인 확장, 유튜브 랭킹 리스트
  - ✅ 퀴즈 선택/플레이/결과, 두뇌 게임 선택/플레이 화면 UI
  - ✅ 말벗 챗봇, 마이페이지, 구독 결제 화면 UI 및 이용 제한 안내 다이얼로그
  - ✅ 더미 데이터 생성·관리 유틸 작성(이후 실제 데이터 레이어로 무손실 교체 가능한 형태)
  - ✅ 반응형(모바일 우선) 및 전체 사용자 플로우 클릭 순회 검증

  **테스트 체크리스트**: Playwright MCP로 홈 → 퀴즈 → 결과 → 홈, 홈 → 게임 → 홈, 비로그인 상태에서 `/chat` 진입 시 `/auth/login?redirect=/chat` 리디렉션 및 로그인 후 복귀 확인

## ✅ Phase 3: 두뇌 게임 실기능 구현 (F004, F005)

- ✅ **Task 007: 두뇌 게임 로직 레이어 구현**
  - ✅ 카드 매칭: 카드 덱 생성/셔플/짝 판정 로직을 UI 비의존 순수 함수로 구현(`lib/games/logic.ts`)
  - ✅ 슐테 표: 4x4 격자 생성, 순서 검증, 소요시간 측정 로직 구현
  - ✅ 격자 셀 44x44px 이상 확보를 위한 그리드 크기 상한(`SCHULTE_MAX_SIZE`) 제약을 로직 레벨에 반영
  - ✅ 로직 단위 테스트 작성(Vitest, 프레임워크 비종속 확인, 11개 테스트 통과)
  - ✅ (2026-09-06 수정 완료) 검증 중 발견했던 React hydration mismatch(Math.random 기반 useState 초기화)를 마운트 이후 useEffect에서 덱/격자를 생성하도록 바꿔 해결

- ✅ **Task 008: 두뇌 게임 플레이 화면 연동 및 기록 저장**

  - ✅ "다시 하기"(동일 게임 재시작) / "홈으로" 동작 구현
  - ✅ `lib/games/supabase-repository.ts` 구현, `brain_game_attempts` 기록 저장(비로그인 시 `user_id` null 허용) — RLS 정책상 허용됨을 마이그레이션으로 확인

## Phase 의존성 요약

```
✅ Phase 1 (골격)
   ├─→ ✅ Phase 2 (UI/더미) ─┬─→ ✅ Phase 3 (두뇌 게임)   ← 콘텐츠 의존 없음, 완료
   │                        ├─→ Phase 4 (배치 파이프라인) ← ✅ Open Question 확정 완료(Phase 0 Task 1), 착수 가능
   │                        │      └─→ Phase 5 (퀴즈)     ← 배치 인프라 재사용
   │                        └─→ Phase 6 (계정/접근성)
   │                               └─→ Phase 7 (챗봇/수익화) ← ✅ Open Question 확정 완료(Phase 0 Task 2·3, F001~F008 무료유지 여부만 보류) + 광고/PG 계정 개설·계약 필요
   └───────────────────────────────────→ Phase 8 (품질/배포)
```

- **Phase 3**은 완료되었습니다(2026-09-06). Phase 4도 정책 확정이 끝나 착수 가능합니다.

- **Phase 7**은 정책 확정(SDK/PG사 선정 포함)은 끝났지만 F001~F008 무료유지 여부가 보류 상태이므로 착수 직전 재확인이 필요하고, 선정된 Google Ad Manager/토스페이먼츠의 실제 계정 개설·심사·계약(리드타임 있음)은 Phase 4 시점부터 병행 착수를 권장합니다.
