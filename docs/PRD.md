# 손주야놀자 MVP PRD

## 🎯 핵심 정보

**서비스명**: 손주야놀자 — 손주가 놀아주듯 매일 챙겨주는 서비스라는 의미
**목적**: 어르신이 매일 들를 이유가 있는 서비스가 되도록, 비로그인으로도 즐길 수 있는 두뇌 건강 퀴즈·두뇌 게임·건강 상식·인기 유튜브 랭킹·오늘의 날씨운세를 한 곳에 모으고, 그 위에 AI 말벗 잡담 챗봇을 더해 재방문을 유도한다.
**사용자**: 60대 이상 고령층 중 스마트폰/PC로 간단한 웹 서비스를 이용할 수 있는 사용자.

> 본 프로젝트는 기존 "약관 돋보기"(보험약관 요약 서비스) 코드베이스를 재활용한다. 해당 아이디어는 보험업법상 단정적 답변 리스크로 폐기되었고, 이번 컨셉으로 완전히 대체한다.
>
> 최초 기획 당시 포함했던 "TV·라디오 편성표 통합" 기능은 국내에 이용 가능한 무료 공식 편성표 API가 없어(공공데이터포털엔 통일부의 북한 TV 편성표 API만 존재) 구현을 포기하고, 대신 비로그인 콘텐츠를 아래처럼 확장하는 방향으로 전면 개정했다.

## 🧭 핵심 설계 판단 (MVP 범위)

- **로그인은 부분 필수**로 설계한다. "매일 들어오고 싶은" 서비스가 목표이므로 홈 페이지(비로그인 컨텐츠 허브)의 두뇌 건강 퀴즈·두뇌 게임·건강 상식·유튜브 랭킹·날씨운세는 비로그인으로 즉시 이용 가능하게 하여 진입장벽을 낮춘다. 반면 AI 말벗 챗봇의 이용 횟수 추적과 구독 결제는 사용자를 특정해야 하므로, 챗봇 이용 시점에 로그인을 요구한다(미로그인 상태로 챗봇 진입 시 로그인 페이지로 유도).
- 기존 프로젝트에 이미 Supabase Auth 기반 회원가입/로그인/로그아웃 화면(app/auth/*)이 스캐폴딩되어 있으므로, 신규 인증 시스템을 만들지 않고 그대로 재사용한다.
- **두뇌 게임은 카드 매칭(그림 짝맞추기)과 숫자 순서 맞추기(슐테 표)를 MVP에 우선 포함**한다. 두 게임 모두 규칙이 극히 단순해 콘텐츠를 매번 새로 제작할 필요 없이 로직만으로 무한히 생성 가능하고, 참고할 수 있는 오픈소스 구현이 많아 1인 개발 부담이 적다. 스도쿠는 콘텐츠 생성 자체는 라이브러리로 해결 가능하지만, 9x9 격자는 셀 크기가 작아져 본 서비스의 접근성 하한선(버튼 44x44px 이상)과 정면으로 충돌할 위험이 크므로 MVP 이후로 미룬다. 십자말풀이는 매번 새로운 단어/힌트 콘텐츠를 수작업 또는 AI로 제작해야 해 콘텐츠 제작 부담이 가장 크므로 마찬가지로 제외한다.
- 두뇌 게임은 퀴즈와 달리 AI 격려 코멘트용 결과 페이지를 별도로 두지 않는다. 완료 시 소요시간/성공 여부를 플레이 화면 안에서 바로 보여주는 것으로 충분하다고 판단해 MVP 범위를 최소화했다.
- 건강 상식 카드는 의료 자문이 아닌 참고용 정보로만 서술한다(단정적 진단/처방 표현 금지, 참고용 안내 문구 필수 명시). 이는 "약관 돋보기" 폐기 사유였던 법적 리스크 원칙과 동일한 기준을 적용한 것이다.
- 어르신 인기 유튜브 시청 순위는 YouTube Data API v3(공식 무료 API, 일일 쿼터 제공)를 사용한다. TV 편성표와 달리 실제로 사용 가능한 공식 데이터 소스가 존재하므로 채택했다. 다만 쿼터 제한을 고려해 실시간 조회가 아니라 하루 1~2회 배치로 데이터를 가져와 캐싱하는 방식으로 설계한다.
- AI 말벗 챗봇은 **단계형 이용 제한 로직**을 적용한다: 1회차 대화는 로그인 시 무료, 2회차부터는 광고 시청 후 이용, 광고를 계속 보고 싶지 않다면 월 990원 구독으로 무제한 전환. 이 횟수 기준(1회/2회)과 가격(990원)은 향후 변동 가능한 정책 값이며, 세부 리셋 주기 등은 Open Question으로 남긴다.

## 🚶 사용자 여정

```
1. 홈 페이지 (비로그인 컨텐츠 허브)
   ↓ 카드 선택

   [두뇌 건강 퀴즈 카드]
     → 두뇌 건강 퀴즈 페이지 (노래 맞추기 / 상식 퀴즈 / 기억력 게임 중 선택, 비로그인 가능)
     ↓ 퀴즈 플레이 페이지 (문제 풀이)
     ↓ 완료
     퀴즈 결과 페이지 (점수 + AI 격려 코멘트)
     ↓ [다시하기] → 퀴즈 플레이 페이지 / [홈으로] → 홈 페이지

   [두뇌 게임 카드]
     → 두뇌 게임 페이지 (카드 매칭 / 숫자 순서 맞추기 중 선택, 비로그인 가능)
     ↓ 두뇌 게임 플레이 페이지 (게임 진행, 완료 시 결과 인라인 표시)
     ↓ [다시하기] → 동일 게임 재시작 / [홈으로] → 홈 페이지

   [건강 상식 카드 열람] → 홈 페이지 내 카드 확장 열람 (별도 페이지 이동 없음)

   [어르신 인기 유튜브 시청 순위 열람] → 홈 페이지 내 랭킹 목록에서 영상 선택 → 새 탭에서 유튜브 재생

   [오늘의 날씨·운세 확인] → 홈 페이지 상단 요약 확인 (별도 페이지 이동 없음)

   [말벗 챗봇 선택]
     → 로그인 여부 체크
        [미로그인] → 로그인 페이지 → 로그인 성공 → 말벗 챗봇 페이지로 복귀
                    (신규 사용자는 로그인 페이지에서 회원가입 페이지로 이동 → 가입 완료 → 자동 로그인 → 복귀)
        [로그인 상태] → 말벗 챗봇 페이지
     → 오늘 날씨·오늘의 운세 인사와 함께 대화 시작
     ↓ 대화 진행에 따라 단계형 이용 제한 적용
        [1회차 대화] → 로그인 상태면 무료로 진행
        [2회차부터] → 광고 시청 선택 → 리워드 광고 시청 완료 → 대화 계속
        [광고 반복이 부담스러운 경우] → 구독 선택 → 구독 결제 페이지 → 결제 완료 → 무제한 대화로 전환

2. 로그인 후 공통 흐름
   마이페이지 진입 → 글자 크기·고대비 모드 조정, 구독 상태 및 챗봇 이용 현황 확인
     ↓ 구독 변경/해지 필요 시 → 구독 결제 페이지로 이동
```

### 3. MVP 이후 기능 (제외)

- 스도쿠: 9x9 격자에서 셀 크기가 작아져 접근성 하한선(버튼 44x44px)과 충돌할 위험이 커 별도 레이아웃 검증 후 재검토
- 십자말풀이: 매번 새로운 단어/힌트 콘텐츠를 제작해야 해 1인 개발 MVP에 부적합
- 건강 상식 카드 아카이브/검색(과거 카드 다시보기)
- 대화 히스토리 기반 장기 기억 개인화 프로필
- 소셜 기능 (공유, 커뮤니티, 가족과 퀴즈/게임 결과 공유)
- 프로필 상세 관리(아바타, 자기소개 등)
- iOS/Android 네이티브 앱 (아키텍처 가이드라인은 Open Question 참고)

## ♿ UI/UX 요구사항 (접근성 하한선 + 모던 디자인 절충)

어르신 대상 서비스이므로 접근성 원칙은 타협 불가 하한선으로 유지하되, 그 안에서는 최근 모던 웹사이트들의 비주얼 트렌드(카드형 레이아웃, 부드러운 그림자, 세련된 컬러 팔레트, 넉넉한 여백)를 적용해 "촌스럽지 않은 어르신 친화 서비스"를 지향한다.

### 접근성 하한선 (타협 불가)
- **폰트**: 본문 최소 16pt 이상, 핵심 정보(챗봇 메시지, 퀴즈/게임 문제, 건강 상식 카드 제목)는 20pt 이상. 줄간격(line-height) 1.6배 이상
- **색상 대비**: WCAG 권장(4.5:1)보다 강한 최소 7:1 대비율 (텍스트/배경, 버튼/배경 모두)
- **터치 영역**: 버튼 최소 44x44px, 버튼 간 여백을 충분히 두어 오터치 방지
- **아이콘**: 아이콘 단독 사용 금지, 텍스트 라벨 병기 필수
- **레이아웃**: 화면당 노출 메뉴/정보 최소화(헤더 메뉴 4개 이내), 다차원 표(그리드) 형태 배제 — 단, 두뇌 게임(카드 매칭, 슐테 표)의 격자형 UI는 게임 특성상 예외로 허용하되, 각 셀이 44x44px 이상의 터치 영역을 확보하도록 그리드 크기(예: 슐테 표는 4x4 또는 5x5)를 제한한다
- 위 기준은 F012(접근성 설정)의 "보통/크게/아주크게" 최소 단계에도 동일하게 적용 — "보통" 단계가 이미 위 하한선을 만족해야 함

### 모던 디자인 적용 방향 (하한선 내에서 자유)
- **레이아웃**: 카드형 컴포넌트(콘텐츠 허브 카드, 퀴즈/게임 카드 등)에 부드러운 그림자(soft shadow)와 넉넉한 radius 적용 — 딱딱한 표 형태 대신 리스트/카드 혼합 구성
- **컬러 시스템**: 채도가 과하지 않은 세련된 톤(예: 딥네이비/테라코타 계열 포인트 컬러 + 뉴트럴 배경)을 쓰되, 포인트 컬러와 배경 간 대비는 위 7:1 기준을 반드시 만족하는 조합만 채택
- **타이포그래피**: 큰 글씨 안에서도 제목/본문 위계가 느껴지도록 굵기(weight) 차이를 적극 활용 (색상 대비만으로 위계를 주지 않음)
- **모션**: 화면 전환/로딩에 과하지 않은 부드러운 트랜지션 정도만 적용, 정보 파악을 방해하는 애니메이션(자동 캐러셀, 빠른 전환 등)은 배제
- shadcn/ui + TailwindCSS 기존 스택으로 구현 가능한 수준에서 진행하며, 별도 디자인 시스템 신규 도입은 하지 않는다
